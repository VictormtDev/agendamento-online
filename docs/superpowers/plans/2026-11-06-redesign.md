# Redesign Encaixe — Plano de implementação

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Aplicar a identidade Encaixe (tema Eucalipto) em todo o `apps/web`, com um design system próprio, header responsivo e uma faixa de dias no lugar do date input nativo.

**Architecture:** Os tokens ficam no `@theme` do Tailwind v4 (`src/index.css`). Os componentes de apresentação vivem em `src/components/ui`. As telas trocam as classes `slate` soltas por esses componentes e tokens. A lógica de data nova é pura e testada (`src/lib/day-strip.ts` e `src/lib/slot-periods.ts`), e é composta de helpers que já existem (`shiftDate`, `formatDayLabel`, `formatTime`).

**Tech Stack:** React 19, Tailwind v4, lucide-react (nova), Vitest + Testing Library, date-fns/@date-fns/tz (já existentes).

**Spec:** `docs/superpowers/specs/2026-11-06-redesign-design.md`

## Global Constraints

- Nenhuma alteração em `apps/api`, `src/api/*`, `src/features/auth/auth-schemas.ts`, nos schemas de `service-form` ou em qualquer lógica, como mutations, regras de cancelamento e guards.
- Textos, labels, nomes acessíveis e roles usados nos testes não mudam. A única exceção são os três pontos do date input em `booking-flow.test.tsx` (Task 5).
- Uma dependência nova: `lucide-react`. Fontes por `<link>` do Google Fonts, sem pacote.
- Ícones lucide são sempre decorativos (`aria-hidden`). Botões só com ícone têm `aria-label`.
- Não criar elementos novos com role `region` (um `<section>` com `aria-label` ou um `aria-labelledby`) nas páginas de horários e de agenda: `provider-schedule.test.tsx:55` conta as regions.
- Textos novos em português, frases curtas, sem CAPS LOCK em labels.
- Contraste AA, foco visível (`focus-visible:outline-2 outline-offset-2 outline-eucalyptus-600`) e layout responsivo até 360px.
- Ao fim de cada task: `npm test -w apps/web` e `npm run build -w apps/web` verdes. Depois `npm run lint` e `npm run typecheck` na raiz. Então commit e **parada para o usuário conferir no navegador**.
- Commits: `<tipo>(web): <descrição em português>`, com o trailer `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.

## Review Focus

1. **Faixa na semana do "hoje" quando o fuso do provider difere do device:** o primeiro dia é `todayIn(provider.timezone)`, e não o dia do device. Coberto na Task 5 pelo teste da seta desabilitada e do primeiro dia.
2. **Duplicação de controles no jsdom:** o menu mobile, se ficar sempre montado, duplica "Sair" e os links e quebra `findByRole('button', { name: 'Sair' })`. O painel mobile só é montado quando aberto. Coberto na Task 2.
3. **Horário na virada de período (12:00, 18:00):** 12:00 é Tarde e 18:00 é Noite, no fuso do provider. Coberto na Task 5 (`slot-periods.test.ts`).
4. **Nome com espaços extras ou uma palavra só no Avatar:** `'  bruno   lima '` → `BL`, `'Zeca'` → `Z`. Coberto na Task 1.
5. **Ícone dentro de link ou botão alterando o nome acessível**, por exemplo "Agendar Massagem": os ícones são `aria-hidden`, e os testes existentes da Task 4 continuam valendo.
